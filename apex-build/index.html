Apex satellite platforms: what to build

Apex builds satellite buses. We are building a 3D model of each of their three platforms. Start with Nova. This page has the process and rules for all platforms; each platform page has its specs, options, parts, and QA.

2How the work runs

Confidential: all Apex files (CAD, reference images, this brief) are covered by the NDA. Do not share them outside your team or use them for anything else.
  1. Render template. Build the render template (section 6) and send it for approval. If you cannot build it, tell us and VNTANA will provide it.
  2. Materials. Build a material cube for each key material. Apex approves them. Approved materials go into the material library (section 5).
  3. Build the model from the VNTANA CAD, with library materials only: stowed, deployed, and the deploy animation (section 4).
  4. Set up renders with the approved render template.
  5. Upload to the Apex workspace on VNTANA, run the QA check, and tell us it is ready.
  6. Review: Apex and VNTANA leave notes as annotations on the asset. Fix, re-upload as a new version.

  • All textures packed in each .blend. One .blend attached per asset.

Material cube (for approval)

  • One beveled cube per material, 20 cm, with the texture at real-world scale.
  • Render it in the render template, in both environments (Studio and Dark Space), hero camera.
  • Upload each cube to the Apex workspace as an asset named MAT_<NAME>_v1, with the .blend attached and the reference photo it matches.
  • After approval, the material is locked. Use it as is. If a part needs a finish that is not in the library, make a new cube and get it approved first.

6Render template

  • You build the template first and upload it as APEX_Render_Template for approval. If you cannot, tell us and VNTANA will provide it. After approval, start every file from it. Do not copy cameras into your own scene: the color settings do not come with them.
  • 9 cameras: 01_Hero, then 02 to 09 for the standard views (front, sides, back, top, bottom, detail).CONFIRM names
  • 2 environments, packed in the file: Studio (clean product lighting) and Dark Space (black background, hard sun light).
  • Cycles. Color Management: ACES 1.3, exposure 1.0. 2048 × 2048, transparent background. No extra lights.
  • Renders run in VNTANA Advanced Renders from the attached .blend.

7Model rules

Geometry

  • Real-world size in meters, from the CAD VNTANA sends you. This CAD is the outside only: internal parts are removed before you receive it. Model only what is in the CAD; do not add internal parts.
  • Clean geometry where visible.
  • Triangle budgetTBD

Naming

  • Every part is a separate, named mesh with the platform prefix: NOVA_, ARIES_, COMET_. For example NOVA_BUS, NOVA_SADA_L, NOVA_ARRAY_L1.
  • Each configurator option is a parent empty named OPT_<GROUP>_<CHOICE>, for example OPT_COMMS_MDL.
  • Moving parts (hinges, SADAs, yokes) have their pivot on the real rotation axis.
  • English names, no spaces, no default names like "Cube.001".

Origin, scale, orientation

  • Origin at the center of the launch interface (separation ring) face. +Z up, toward the payload deck.CONFIRM
  • All transforms applied on static parts (scale 1).

UVs

  • Single 0 to 1 UV space per material; texture density at real-world scale.
