Rules, conventions and the fix hierarchy (click to expand)
UUID RULE (do not forget): assets already keyed into Costco's back office must be fixed IN PLACE via versioning (the UUID is what the app loads). Do not adjust rotation in platform settings on an asset that will be re-versioned; orientation fixes belong in the source file. If a reprocessed version comes in rotated wrong, stop: rebuild as a new asset, archive the old one, and flag the UUID change to Daniela. New versions drop to Draft: re-publish after processing.
Viewer presets: Derek is also setting per-asset scene settings (hero-shot camera framing + lighting) during cleanup, so assets load looking right in the viewer.
As uploaded vs Now: the left pill is the state the asset arrived in; the right pill is after VNTANA's cleanup (FIXED marks the ones Derek repaired: decompressed, rescaled, stray nodes removed, reprocessed).
AR scale column: ✓ = world dimensions measured in Blender and plausible for the product (AR will place it true to size); ✗ = wrong units found; 'not checked' = not yet measured.
Fix hierarchy (the product story): 1) platform settings first (pipeline, Max Resolution, Compression Level, Pivot): covers size, texture and grounding problems with zero file touching; 2) decompress-and-reupload only for inputs carrying REQUIRED glTF extensions (Draco, WebP, KTX2, texture transforms): optimization pipelines must reject these by spec, and Convert Only just passes them through unchanged (no optimization, no pivot control), so decode in Blender and re-export raw; 3) Blender surgery ONLY for source defects no optimizer could infer (baked leans, wrong units, placeholder materials, missing textures): logged as VNTANA repairing the vendor's file, with export guidance sent back to the vendor.
Tag convention (platform): 'Live Asset' = fully done: AR-checked, renamed 'ITEM (Production)', description set, Live Public (maps to Shippable here). 'Final Review' = 3D ready but metadata incomplete (description / item number / naming: Daniela's queue; maps to Costco review here). Tags are mutually exclusive: swap Final Review for Live Asset in the same edit that completes the metadata. Where a new asset was created, Daniela updates the back-office UUID (so far: 1288769 -> e3e67fe5, 1321497 -> 43f15396).
Pivot rule: floor-standing products upload with Pivot Point Alignment = Bottom Center; wall-hung = Back Center; hanging = Top Center. Every FIX READY row states its pivot.
Reference check: every row links its Costco PDP for visual comparison (colors, finish, orientation, completeness). Rows marked NO REFERENCE need a PDP link or product photo before they can pass Costco review.
Size goal: every delivered asset under 5 MB (current size in red when over, green when under). Naming rule: asset name = Costco item number, description = product name.
Status legend: Shippable = AR-checked and looks right, correct item-number name, description present: ready for members. Costco review = 3D work done; awaiting metadata (name/description: Daniela) and/or final visual sign-off in AR. In repair = VNTANA actively fixing (corrected file ready or reprocess pending). Vendor action = only the vendor can fix it (missing textures or geometry, unsupported format, low-res source). Pending = not reviewed. Discarded = removed from the workspace, kept for the record.
Triage rules: see the Optimization Settings Guide + the triage order in the cleanup handoff. Fixed files stay in Mexico POC; originals move to the archive workspace. Asset name = item number; description = product name; UUID goes in Costco's back office; must be Live Public for the app.
