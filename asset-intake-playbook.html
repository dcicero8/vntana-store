3D Asset Intake Playbook
VNTANA internal only: names clients and open bugs

Everything we learned triaging roughly 60 vendor-built assets across three client batches (Costco Mexico POC, Accenture/LEGO, J&J OTTAVA), distilled into: the failure classes, how to recognize each one in minutes, the proven fix, and what the website docs and the platform should change. Same taxonomy showed up in all three batches, so these are not client quirks, they are the industry's actual export habits.

1The failure taxonomy

Required glTF extensions the silent killer

Symptom
Every optimization pipeline fails with no output and no useful error. "It just fails no matter what I do." Convert Only may succeed, but see the trap below.
Mechanics
glTF files can list extensions under extensionsRequired. The spec says a loader that does not support a required extension must reject the file entirely. Four members seen in the wild so far: KHR_draco_mesh_compression, EXT_texture_webp, KHR_texture_basisu (KTX2), and KHR_texture_transform (per-texture UV offset/scale/rotate).
Cases
Costco: LG OLED 55C6 (Draco + texture_transform, the transforms were real: 6x tiled stand texture) Costco: air fryer GAF858 + ~6 more failed drafts suspected J&J: WebP + KTX2 + Draco from their web-prep script Accenture: Vespa + sofa (Draco from Blender/Max export)
Detect
Parse the GLB JSON chunk and read extensionsRequired. Takes 5 lines of Python. Also a tell: suspiciously small file (2 to 5 MB) for a complex product means it is already compressed.
Fix
Decode in Blender (import decodes Draco; texture transforms become Mapping nodes, bake them into the mesh UVs per polygon before export), re-export raw GLB with Draco off and a new versioned filename, reprocess through standard optimization. Vendor guidance: export uncompressed; upload what goes INTO your web-prep script, not what comes out.

The Convert Only trap trap

Symptom
"It processed fine but it is 31 MB / 45 MB and none of the settings do anything." Or: a required-extension file that failed everywhere finally "works" on Convert Only.
Mechanics
Convert Only is a pass-through. It tolerates required extensions by not looking at them, ships every triangle untouched, and locks out all other options including Pivot Point Alignment. So the output keeps the input's problems: no optimization, no grounding control, and any required extensions ride along into downstream conversions (USDZ).
Cases
Costco: air fryer Convert Only = 45.8 MB, all 14M tris Costco: LG OLED Convert Only output = byte-for-byte problem pass-through, still floating 6.3 cm Costco: 1876771, 901k triangles kept, heavy GPU load on mobile despite 4.4 MB
Rule
Convert Only is for assets that are ALREADY final web files needing zero changes. For everything else, fix the input so standard optimization can run. If you only need "Convert Only with options": Preserve Meshes and UVs with the Polygon Limit raised above the actual count and Max Resolution above the largest texture behaves like a pass-through that still honors pivot and compression settings.

Settings inflation: "max quality" backfires trap

Symptom
The optimized output is BIGGER than the input.
Mechanics
Texture Compression Level 0 re-encodes already-efficient PNGs at lossless and grows them. Small Feature Baking ADDS new baked maps. Draco off ships geometry uncompressed. Stacking "best quality everywhere" settings is how a 22.5 MB input became a 29.2 MB output.
Cases
Accenture: LEGO toucan 22.5 to 29.2 MB on max-quality settings; DEFAULTS produced 1.2 MB (24x smaller) with no visible difference in matched-camera close-ups
Rule
Defaults first, always. Raise a setting only after a render proves the default lost something visible. Measured on photographic textures: Compression Level 1 vs 2 is nearly invisible (mean delta 6 to 8 per 255); Max Resolution loss is the visible cliff because detail is gone permanently.

Scan-class assets: keep textures, give up polygons proven recipe

Recipe
Preserve Meshes and UVs + Max Resolution 4K + Compression Level 2 + Pivot Bottom Center. Settings only, zero file touching.
Cases
Accenture: sofa scan 40.1 MB Convert Only to 6.5 MB, weave visually identical at thread-level zoom
Why
On photogrammetry and scan assets the texture carries the realism and the mesh is bloated. Decimation is nearly free visually; resolution loss is not. The inverse of CAD assets.

Source defects needing file surgery last resort

Doctrine
Platform settings first, decompress-and-reupload second, Blender surgery ONLY for defects no optimizer could infer. Always framed as VNTANA repairing the vendor's file, with export guidance sent back. Never imply going back to the source is the only fix.
The list
  • Baked leans: the model is tilted in the geometry itself. Tell: a bloated bounding-box depth ("reads deep for a cooler" = lean signature). Found 13.3 and 7.1 degree leans on two wine coolers from the same vendor. Fix: minimal-bounding-box rotation solver, with a footprint-gain guard (under 4 percent improvement = shape-driven false positive, like a TV slab with feet).
  • Wrong units: inches or cm exported as meters. A 35.9-meter-tall stand mixer. Fix: rescale 0.0254x or 0.01x, reground.
  • Viz-color / placeholder materials: raw CAD exports wearing part-ID colors (pure green/yellow/cyan) or flat gray placeholders; "stainless renders black" = black base color + metallic 1 + roughness 0. Fix: retint against the product PDP.
  • Omitted metallicFactor: glTF defaults it to 1.0, so untextured wood/fabric renders as gray metal. Check material JSON, not just the viewport.
  • Tiny baked textures: KeyShot per-part bakes at 250 px make LCD digits and logos unrecoverable mush. Only the vendor's export settings can fix resolution; repainting is best-effort.
  • Stray helper nodes: Helper001, Particle_View, lux_root, leftover cameras. They inflate the bounding box and make the product float in AR. Delete before export.
  • Transmission glass: KHR_materials_transmission renders OPAQUE in AR Quick Look / USDZ. Fix: alpha-blend glass (alpha around 0.18, blend mode). Web viewer and USDZ both look right after.

Legacy and unsupported formats vendor action

Cases
.3ds cannot embed textures: the referenced PNGs never arrived, plus pre-PBR Phong materials .max is not a pipeline format at all: it sat as an inert 276 MB attachment and never entered processing
Rule
Format preference to publish in docs: GLB, then FBX with embedded media, then OBJ zipped with textures, then STEP (geometry only). Anything older goes back to the vendor for re-export.

3Platform gotchas and open bugs

Versioning rotation accumulation open bug, confirmed

What
Rotations accumulate across versions on an asset record (confirmed by Neven and Fatima). Add rotation to a model, create versions, and every new version comes out differently mangled: flipped, tilted, flipped again. Repro pair preserved: broken asset 7e910ec2-bca7-4733-9d42-d9bcc1da45bf vs clean e3e67fe5-6a9d-44ce-bfb1-e3450bc2faed, same byte-identical file, upside down vs correct.
Workaround
Never adjust rotation in platform settings on an asset that will be re-versioned; orientation fixes go in the FILE. A contaminated asset cannot be cleaned: rebuild as a new asset and re-key any external UUID references.

Smaller gotchas worth documenting

  • Convert Only locks out everything, including Pivot Point Alignment. The workaround is Preserve Meshes and UVs with limits raised above the file's actual counts.
  • Same-name re-upload silently keeps the old geometry. Every re-export needs a new versioned filename (v2, v3).
  • New versions drop to Draft: re-publish after processing or the public link serves the old version.
  • Pivot cheat sheet: floor-standing = Bottom Center; wall-hung = Back Center; console-or-wall (soundbars) = Back Bottom Center; hanging = Top Center.
  • Output can exceed input with lossless texture settings and Small Feature Baking stacked on (see settings inflation above). No warning fires today.

4The QA rig: what runs on every customer asset

When a customer asset fails (or just looks wrong), Derek runs it through an automated battery BEFORE anyone burns time guessing: vntana-store/admin/qa-asset.py file.glb [--usdz f] [--expect W D H] [--fix]. It returns a verdict with per-check flags in about a minute, so the report back to the team is "here is the root cause" instead of "it fails." Review ask (Jure + team): this list below IS the rig. Check it against what the platform pipeline actually trips on: anything we should add, anything checked twice, and anything here the platform could absorb at ingest.

Stage 1: header forensics (seconds, no Blender)

Parses the GLB JSON chunk directly.

  • extensionsRequired: Draco, WebP, KTX2, texture transforms, or ANY unknown required extension (each one = the rejection class from section 1). This is the first check because it explains total failures instantly.
  • Empty or rig-only export: zero meshes (the J&J camera rig and 132-byte scene cases).
  • Viz-color materials: pure CAD part-ID colors (green/yellow/cyan), with an exception for genuinely emissive parts.
  • Black-metal: black base color + metallic (the "stainless renders black" wine-cooler defect).
  • Omitted metallicFactor on materials named wood/fabric/plastic (glTF defaults it to 1.0 = gray metal).
  • Stray nodes: Helper*, Particle*, dummy, lux_root, leftover cameras, untranslated CAD names (floats-in-AR causes).
  • Zero or negative scales (mirrored or collapsed nodes).
  • Tiny textures (the KeyShot 250 px bake problem).
  • Transmission glass (renders opaque in AR Quick Look; needs alpha-blend conversion).
  • Animation payload size (the J&J dense-baked-animation case).
  • Generator string for provenance (KeyShot, Blender, Max, VNTANA output).

Stage 2: geometry truth (headless Blender import)

  • World dimensions + units sanity, with an optional gate against the real product dims from the PDP (--expect W D H). Catches inches-as-meters and cm-as-meters instantly.
  • Lean detector: a minimal-bounding-box rotation search finds tilts baked into the geometry (the 13.3 and 7.1 degree wine coolers). Guard: if straightening shrinks the footprint less than 4 percent, it is shape-driven (TV slab with feet, curvy product) and reports as a note to confirm in the side render, not a flag.
  • Grounding: base must sit at z = 0 or it floats/clips in AR.
  • Centering of the model on origin.
  • Three renders: front, side against a visible floor plane (lean + grounding proof), and three-quarter.

Stage 3: AR gate (USDZ, numeric)

  • Checks the generated USDZ with usd-core: upAxis = Y, metersPerUnit correct, bounding-box min Y at 0 (grounded), dimensions match the real product. Numbers, not eyeballs: AR scale problems are caught before anyone opens a phone.

Output

  • Verdict (PASS / NEEDS WORK) with every flag naming its fix.
  • Pivot recommendation for the upload (Bottom Center / Back Center / Back Bottom Center / Top Center by product type).
  • --fix auto-repair: exports a _qafix.glb that is straightened, grounded, centered, and decompressed, for the cases where the defect is mechanical.
  • The workflow: asset fails on platform, Derek runs the battery, the team gets a root-cause report plus a ready file or settings recipe instead of a mystery.

5What to change: docs and platform punch list

Website / documentation

  • Publish the intake decision table (section 2) on the upload docs page: pipeline by source type is the single highest-leverage piece of guidance.
  • Add a "before you export" vendor checklist: no Draco/WebP/KTX2 at export, no web-prep scripts before upload, delete helper nodes and cameras, embed textures, real PBR materials (set metallicFactor explicitly), 2048 px minimum textures (4096 where there is text), versioned filenames.
  • Document defaults first with the toucan numbers: max-quality settings made the file bigger; defaults were 24x smaller with no visible difference.
  • Document the scan-asset recipe (PMUV + 4K + Level 2) and the CAD-vs-scan intuition: scans give up polygons, CAD gives up texture resolution.
  • State plainly that Convert Only disables all optimization options including pivot, and when that is acceptable.

Platform asks

  • Detect extensionsRequired at upload and show an actionable message ("this file requires Draco decoding / texture transform support; optimization pipelines will reject it; here is how to export without it"). Today the user gets a silent failure and blames the platform.
  • Better: decode Draco and bake texture transforms server-side at ingest. Blender does both in one import; this entire failure class would disappear.
  • Warn when output size exceeds input: it always means the settings are fighting the optimizer.
  • Fix the versioning rotation accumulation bug (repro pair above; fix requested of the team).
  • Consider allowing Pivot Point Alignment on Convert Only: grounding is the one thing pass-through users still need.
