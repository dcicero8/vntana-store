Project briefWhat we are building

DeliverableLive 3D + AR chair configurator embedded in the SteelSeries PDP image gallery: shopper picks model, finish, and electronic modules, sees the chair update in real time, and adds the configured chair to cart. Open questionsFor Neven (configurator + commerce scoping)

  • Build approach. This demo runs as ONE combined GLB with named module nodes toggled at runtime on the public npm-bundle viewer. For production, is that the supported path, or do we build on the 3.0.0 configurator module (Wilbert pattern)? What is supportable for a customer vs demo-only?
  • Animation / updates. Requirement: module toggles update instantly and the fans/glow animate continuously. On the public npm viewer this only works while its render loop runs (this page keeps auto-rotate on as a workaround). Does 3.0.0 handle this natively, or is there a supported render API?
  • Commerce integration. What do you need from the SteelSeries stack to produce the integration plan: platform, cart API, how a configuration maps to SKU/price? Session with Jakub Prus + Timothy Stoneberg to schedule.
  • AR. Should AR reflect the shopper's selected configuration (per-config USDZ, 34 variants) or a hero configuration per model? What does that do to scope?
  • PDP embed. Constraints for living inside their gallery: iframe sizing, lazy load, performance budget on the PDP.
  • Scope inputs. What granularity do you need from the config matrix (asset count, interactions, integration points) for you and Ashley to price it?

Open questionsFor Toni (assets + product rules)

  • CAD coverage. Do we receive native CAD for ALL pieces, including the 4 electronic modules, or does VNTANA model the modules from references? This is the biggest driver of cost and timeline.
  • Asset status. For each part: what source files exist, and are any textured? If your creative team can hand over files with materials intact, asset prep drops out of the quote. A CMF/material spec (mesh fabric, plastics, logos) works too.
  • Module rules. Does the Main Unit have to be present for the other 3 modules to function (does it gate them), or are all 4 fully independent?
  • Module finish. Do the electronic modules come in both Black and White, or one fixed finish?
  • SKUs. Is each of the 34 end configurations its own SKU, or are modules separate line items added at cart?
  • Stack. Which eCommerce platform serves the PDPs, and when can we get Neven together with Jakub and Timothy?
  • Timeline. Target launch window, and when do you need the quote to make a decision?

PlanWhat we need to make it happen

  • 2. Rules sign-off from Toni: module gating, finishes, SKU mapping (the configuration matrix sheet captures these).
  • 3. Commerce scoping session: Neven + Jakub/Timothy, producing the high-level integration plan.
  • 4. Quote + timeline from Ashley once 1-3 land: asset prep, configurator build, integration, launch.
